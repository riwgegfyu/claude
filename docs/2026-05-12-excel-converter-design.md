# 版本计划 → 测试用例导入模板 转换工具

## 概述

命令行工具，将"5月财辅例行版本清单"（版本计划）中的数据按规则自动填入"测试用例导入模板"。

## 技术栈

Node.js CLI，依赖：`xlsx`（Excel读写）、`inquirer`（交互选择）、`mammoth`（docx解析）

## 流程

版本计划.xlsx → 用户选择sheet页 → 逐行读取数据（从第3行开始）→ 解析R列引用 → 提取.docx对应点的内容 → 填入测试用例模板的"测试用例"sheet

## 模块

### cli.js — 入口
- 用 inquirer 列出所有有效 sheet（排除空sheet和Sheet2/Sheet3等），用户多选
- 串联解析→转换→写入流程，输出每行处理进度
- 处理完后输出统计：成功/跳过/失败行数

### parser.js — 读取版本计划
- 读取版本计划 Excel，将每个选中 sheet 的第3行起的数据转为结构化对象
- 从 R 列（系统方案概述）中正则提取文档文件名和点数，如 `《2026年档案系统需求方案.docx》第21点` → `{doc: "2026年档案系统需求方案.docx", point: "21"}`

### docx-reader.js — 解析需求方案文档
- 用 mammoth 将 .docx 转为纯文本
- 按"第N点"模式匹配对应段落，提取实现方案内容
- 解析失败时返回 null，由调用方回退显示原文引用

### writer.js — 写入测试用例模板
- 打开测试用例导入模板，在"测试用例"sheet 追加数据行
- 按规则填写各列（B/G/H列按拼接规则，C/D/E/F/N列填固定值，其余留空）

## 填写规则

| 目标列 | 字段 | 规则 |
|-------|------|------|
| B | 用例名称 | `{O列测试案例编号} {P列综调标题}` |
| C | 测试类型 | 固定 `功能测试` |
| D | 级别 | 固定 `P3` |
| E | 评审状态 | 固定 `通过` |
| F | 用例分组 | 固定 `自定义分组/自定义子分组` |
| G | 关联需求 | `{G列综调单号} {P列综调标题}` |
| H | 前置条件 | 多行文本（详见下文） |
| N | 适用阶段 | 固定 `系统测试` |
| 其他列 | — | 留空 |

### H列（前置条件）格式

```
修正前业务场景描述：无
测试省份：{W列值}{若W列为"提出省测试"则追加（{U列}）}
涉及省份：{V列}
测试前提：无
测试场景：无
测试要点：{从.docx提取的第N点实现方案内容}
```

## 错误处理

- .docx 解析失败 → 测试要点回退显示原文引用
- 找不到对应点数 → 同上回退
- O列或P列为空 → 跳过该行，输出警告
- 版本计划数据行全空 → 跳过
